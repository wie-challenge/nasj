## 6. Defects found by the new tests

1. **Schedule-change clock error (Batch 10).** The first implementation treated an approved schedule change as
   the current time rather than as a replacement deadline, which reported `OVERDUE` for a batch whose deadline
   had legitimately moved. Fixed: `now` is always the real clock; the approved change replaces the deadline.
2. **Pricing arithmetic expectation (Batch 8).** An initial test expectation omitted the fixed transport and
   overhead lines. The implementation was correct and consistent with the Batch 7 simulator baseline
   (2205.000 TND); the test was corrected.

## 7. Honesty guarantees enforced in code

These are the constraints most likely to be quietly violated by a "helpful" implementation, so they are
enforced structurally:

- Unknown capacity is `null`, never `0` and never `Infinity`, in ranking, allocation and simulation.
- Hours are never converted to pieces; `unitType !== 'PIECES'` is an explicit blocker.
- Missing observed time yields `UNAVAILABLE`, never an hourly rate derived from an assumed duration.
- Forecast error metrics are `null` when no comparable observation exists — an empty set is not a perfect
  score.
- Agreed, earned, payable, simulated and verified compensation are five separate fields with a note stating
  they are never combined; verified paid is `0` because no verified evidence exists.
- Cohorts below 5 are suppressed entirely, not masked.
- Notification plans return `SKIPPED_NO_OPT_IN` or `UNDELIVERABLE_NO_PROVIDER`; nothing claims delivery.
- Sample work cannot start without positive agreed compensation.
- Recommendations are advisory; only an artisan's own acceptance moves quantity to committed.
- Support requests are never read by any ranking function, so they cannot become an exclusion criterion.
