Resolve and document these design choices during development before claiming acceptance:

- Use the same explicit weekly calendar/timezone and boundary convention everywhere; existing declarations use instants and the UI says “per week.” Proposed default is Africa/Tunis with documented half-open periods; verify and reconcile the existing inclusive commerce delivery-date checks before adopting it.
- Count unexpired held offers as reserved and accepted obligations as committed, without double counting accepted offers as reservations. Expired/declined offers must not hold new capacity. Define completion/cancellation release against actual domain states; do not assume all historical accepted offers consume capacity forever.
- Reconcile superseded and replacement declarations for the same artisan/craft/unit/effective period. Revision must not hide commitments or bypass offer limits. Return an explicit deficit if declared capacity falls below commitments; preserve obligations and make remaining capacity zero rather than inventing negative availability.
- Keep HOURS and PIECES separate. A pieces commitment cannot be subtracted from hours without a versioned, disclosed conversion; show an unknown constraint when no approved mapping exists. Define how cross-week commitments are allocated before reporting period totals.
- Serialize projection-sensitive writes using the existing transaction/locking discipline. Do not introduce a new amendment workflow in this slice; refer changes to accepted terms to its existing separate backlog story.
